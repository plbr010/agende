# Contratos reais para frontend, backend e Cursor

Base de aplicação `9a8625ae2182e06716f47de3bc8da9051f898e3a`. Nenhuma alteração do Cursor sobrescrita. Contratos de schema descritos abaixo estão completos em staging; produção ainda precisa da janela 3+5. Tipos reais: `src/lib/supabase/database.types.ts`; adaptadores/validação prevalecem sobre rótulos da interface.

| Fluxo | Entrada e retorno reais | Autorização/invariantes |
|---|---|---|
| Catálogo | `list_public_booking_catalog(p_slug)` → nome/slug/timezone/horizon_days/min_lead_minutes/services/professionals; adaptador converte snake_case para camelCase | Leitura anon; preço/duração por profissional no servidor; perfil público elegível |
| Horários | `list_public_available_slots(p_slug,p_service_id,p_professional_member_id,p_local_date)` → linhas `starts_at`; action retorna `{slots: string[],error?}` | Consulta pública não reserva horário |
| Reserva | `createPublicAppointmentAction({slug,serviceId,professionalMemberId,startsAt,fullName,phone,email,customerNote})` → `{error? ,confirmation?}`; RPC `create_public_appointment` recebe `p_` equivalentes mais `p_ip_hash` | `getUser`, e-mail confirmado/não anônimo; e-mail enviado é o de Auth; rechecagem SQL obrigatória; lock/exclusão e snapshot preço/duração; sem guest. Cookie HttpOnly removido só após confirmação interpretável |
| Área cliente | `list_my_appointments()`; `list_my_reschedule_slots(uuid,uuid,date)`; `reschedule_my_appointment(p_appointment_id,p_professional_member_id,p_starts_at)`; `cancel_my_appointment(p_appointment_id)` | Identidade vinculada, status/antecedência e tenant; lista inclui `service_id`/`professional_member_id` após legado; preservar histórico |
| Busca | `search_public_workspaces(p_city,p_state,p_query,p_postal_code,p_limit,p_offset)` → `{items,total}`; localities `list_public_localities(p_state,p_query,p_limit)` | Front manda CEP null, página 20; consentimento e entitlement; nome profissional só de serviço/profissional elegível. Adaptador aceita nomes encontrados opcionais, até 3, mas RPC atual não os fornece: não inventar “Quem atende”. Flag histórica `DISCOVERY_BACKEND_READY=false` não bloqueia probe real do adaptador |
| Logo/capa | `saveWorkspaceImageAction(_, FormData)` com `kind=logo|cover`, `image`, `publicConsent=true`, `remove=true` quando remover → ActionState `success`/`error`/`subscriptionInactive` | Dono/admin confirmado; workspace vem da sessão, não do browser; `queue_workspace_image_upload` → upload → `swap_workspace_image` compare-and-swap → cleanup. Bucket público `workspace-logos`, consentimento explícito; não usar parâmetro legado logo em settings |
| Foto profissional | `/api/professionals/photo?memberId=UUID[&slug=...]`: GET → WebP/404; PUT bytes com `Content-Type`, `x-image-extension=jpg|jpeg|png|webp`, `x-public-photo-consent=true`, Origin; DELETE sem bytes → `{hasPhoto,cleanupPending}` | Sessão confirmada; dono/admin ou próprio profissional ativo; RLS antes de service role; SQL reautoriza actor; bucket privado `professional-photos`, leitura pública mediada apenas por catálogo elegível |
| Avatar global | `/api/account/avatar` GET/PUT/DELETE; `/api/clients/avatar?clientId=UUID` GET mediado | Avatar opcional do usuário, bucket privado `account-avatars`; apenas vínculo legítimo permite leitura ao estabelecimento; `private,no-store`; não copiar bytes por tenant ou listar clientes globalmente |
| WhatsApp | GET `/api/appointments/whatsapp?id=UUID` → 302 com `Location=https://wa.me/...?...`; erro 422 sem Location; `get_appointment_whatsapp(p_appointment_id)` é a fonte autorizada | Só equipe autorizada/confirmada, status válido e dados atuais; URL não muda status e não envia mensagem; manter clique manual |
| Billing | Edge `stripe-billing` com JWT + ações autorizadas; `stripe-webhook` com assinatura Stripe, verify_jwt=false | Preço/tenant/modo no servidor; evento idempotente e ordenação/reconciliação; webhook TEST não alimenta LIVE; nenhuma chamada do frontend com service role ou secret Stripe |

Imagens: entrada JPEG/PNG/WebP até 4 MiB e 4096×4096, decode/reencode sem metadata, saída WebP até 2 MiB; avatar/foto até 512px, mídia workspace usa limite próprio 512/2048. Headers/erros exatos permanecem em `src/lib/media/http.ts`, `src/lib/client/avatar-image.ts` e nas rotas; manter erro sanitizado, sem credenciais/payload do provedor em logs. Não expor caminhos privados como URL pública de Storage.

Campos opcionais novos devem degradar com ausência sem mudar ACL ou inventar dados. Caso Cursor altere formulário/rota/payload, revisar juntos `database.types.ts`, parser/action, SQL e teste que observa efeito persistido. Não criar novo backend para contornar migration pendente. PR #71 de comercial é independente desta release e não foi tocada.
